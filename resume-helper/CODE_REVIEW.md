# 이력서 작성 도우미 코드 리뷰 및 개선 내역

대상 파일: `resume-helper/index.html` (HTML·CSS·JS 단일 파일, 약 6,000줄)

이 서비스는 신입 Java/Spring 풀스택 개발자용 이력서 편집기입니다. 서버 없이 브라우저에서만 동작하고, 단계별 가이드, 빠른 점검, PDF 저장, OpenRouter 기반 AI 점검과 README 생성, JSON 백업 기능을 제공합니다.

원본은 첫 커밋에 그대로 넣어 두었으므로 `git diff`로 변경 내용을 줄 단위로 확인할 수 있습니다.

## 1. 발견한 문제와 수정 내용

심각도: 🔴 높음 / 🟠 중간 / 🟡 낮음
"재현 확인"은 원본 파일에서 Playwright로 실제 재현한 항목입니다.

### 보안

| 심각도 | 문제 | 원인 | 수정 |
|---|---|---|---|
| 🔴 | **README 미리보기에서 스크립트 실행 (재현 확인)** | `markdownToHtml`이 `&<>`만 이스케이프하고 `"`는 그대로 두었습니다. 그래서 `![a](x" onerror="...")`로 속성을 탈출하거나 `[a](javascript:...)` 링크로 스크립트를 실행할 수 있었습니다. 미리보기 내용은 AI 응답이라, 이력서 내용을 이용한 프롬프트 인젝션으로 localStorage에 저장된 **API 키가 유출될 수 있었습니다.** | 따옴표까지 이스케이프하고, 링크·이미지 주소는 `http(s)`, `mailto`, 상대경로만 허용합니다. `rel="noopener noreferrer"`도 추가했습니다. |
| 🔴 | **AI 점검 결과를 그대로 HTML로 삽입** | `FeedbackRenderer`가 AI 메시지를 `innerHTML`에 넣고, AI가 준 필드 ID를 `onclick="UI.scrollToField('...')"` 문자열에 그대로 끼워 넣었습니다. | DOM API(`textContent`, `addEventListener`)로 그리도록 바꿨습니다. 또 `AI.normalizeResult`가 실제로 존재하는 필드 ID와 문자열 메시지만 남기고, 길이와 개수도 제한합니다. |
| 🔴 | **가져온 JSON 백업 파일로 스크립트 실행** | `sanitizeRichText`가 `<script>` 태그만 지웠기 때문에 `<img onerror>` 같은 코드는 그대로 실행됐습니다. 다른 사람에게서 받은 백업 파일을 열기만 해도 위험했습니다. | 허용 목록 방식의 정화 함수로 바꿨습니다. 허용 태그는 `span`, `strong`, `em`, `br`, `li` 등이고, 속성은 `class="skill-tag"`만 남깁니다. 저장된 값을 불러오거나 파일을 가져올 때 항상 정화합니다. 가져오는 파일은 2MB로 제한하고 문자열 값만 받습니다. |
| 🟠 | 위자드 입력이 HTML로 해석됨 | `setFieldHTML`에 학교명, 담당 역할, 구현 내용, 기술명을 그대로 넣었습니다. `C++ <템플릿>`처럼 입력하면 글자가 사라졌습니다. | 모든 사용자 입력을 `escapeHtml`로 감싸고, 결과도 한 번 더 정화합니다. |
| 🟠 | PDF 점검 박스, README 탭, 위자드 미리보기의 `innerHTML` | 사용자가 입력한 카테고리명이나 프로젝트명이 HTML로 들어갔습니다. | `textContent`를 쓰거나 이스케이프합니다. |
| 🟠 | **"Allow CORS" 확장 설치 권유** | 네트워크 오류가 나면 모든 사이트의 보안 정책을 꺼버리는 확장을 설치하라고 안내했습니다. | 안내 문구를 네트워크·광고 차단 확인으로 바꿨습니다. |
| 🟠 | 연락처를 외부 AI로 전송 | AI 점검 시 이메일, 전화번호, 이름이 OpenRouter와 무료 모델 제공사로 그대로 전송됐습니다. | 형식이 맞는지만 알려주고 값은 가려서 보냅니다(`AI.maskPersonalInfo`). |
| 🟡 | 외부 링크의 `target="_blank"` | `rel`이 없었습니다. | `rel="noopener noreferrer"`를 추가했습니다. |

### 버그

| 심각도 | 문제 (재현 확인) | 수정 |
|---|---|---|
| 🔴 | **대표 프로젝트가 화면에서 사라짐.** 위자드에서 프로젝트 단계를 거치지 않고 완료하면 모든 `.project-item`에 `display:none`이 걸렸습니다. 이 숨김은 저장되지도 되돌려지지도 않았습니다. | 대표 프로젝트(필수)와 내용이 있는 프로젝트는 항상 보이고, 비어 있는 보조 프로젝트만 숨깁니다. |
| 🟠 | **미리보기에서 "돌아가기"를 누르면 자기소개 답변이 삭제됨.** 입력칸이 없는 미리보기 화면에서 `saveCurrentStep()`이 실행되어 `intro = {}`로 덮어썼습니다. | 입력칸이 없는 화면에서는 저장하지 않습니다. |
| 🟠 | **자격증 "건너뛰기"가 동작하지 않음.** 값을 비운 직후 `saveCurrentStep()`이 입력칸 값을 다시 읽어 덮어썼습니다. 또 한 번 건너뛰면 `_certSkipped`가 계속 남아 이후 입력한 자격증도 숨겨졌습니다. | 건너뛸 때는 입력칸을 다시 읽지 않습니다. "다음"으로 넘어갈 때 숨김 여부를 다시 계산합니다. |
| 🟠 | **AI 점검 버튼이 없음.** `runAnalysis`와 `AI` 모듈, CSS(`.outline-btn`)는 있었지만 HTML에 `#analyze-btn`이 없어 기능을 쓸 수 없었습니다. | 버튼을 복구했습니다. API 키 하나로 AI 점검과 README 생성을 모두 쓸 수 있도록 안내 문구도 고쳤습니다. |
| 🟠 | AI 응답이 오지 않으면 버튼이 계속 "점검 중"으로 남음 | `fetch`에 45초 시간 제한을 두었습니다(`fetchWithTimeout`, 실제 대기 테스트로 확인). |
| 🟡 | 나중에 추가한 칸에서는 서식이 그대로 붙여넣어짐 | 붙여넣기 처리기를 초기화할 때 있던 요소에만 연결했었습니다. 이제 문서 단위로 위임해서 모든 칸에 적용됩니다. |
| 🟡 | 파일 다운로드가 일부 브라우저에서 취소됨 | `a.click()` 직후 `revokeObjectURL`을 호출했고, 링크도 문서에 붙이지 않았습니다. 지금은 1초 뒤에 해제합니다(`triggerDownload`). |
| 🟡 | `escAttr`가 `&`를 이스케이프하지 않음 | `A &amp; B` 같은 값이 다시 열면 바뀌었습니다. 공통 `escapeHtml`을 쓰도록 바꿨습니다. |
| 🟡 | 이상한 필드 ID가 저장돼 있으면 선택자 오류로 멈춤 | `getFieldEl`이 ID 형식을 검사합니다. |
| 🟡 | 예시 패널이 화면 밖으로 복원됨 | 창 크기 안으로 위치를 맞춥니다. |

### 성능

| 문제 | 수정 |
|---|---|
| 키를 하나 누를 때마다 `updateCompleteness()`가 A4 분량 측정(강제 레이아웃 계산)을 실행했습니다. | 300ms 디바운스를 적용했습니다. |

## 2. 추가한 기능

- **AI 상세 점검 버튼 복구:** 개인정보 마스킹과 45초 시간 제한을 적용했습니다.
- **단축키**
  - `Ctrl/Cmd + S`: 브라우저의 "페이지 저장" 대신 이력서 내용을 저장합니다.
  - `Esc`: 위자드, PDF 안내, README 생성기, 예시 패널을 닫습니다. 위자드는 입력 내용을 저장한 뒤 닫습니다.
- **JSON 가져오기 덮어쓰기 확인:** 작성 중인 내용이 있으면 바꾸기 전에 확인합니다.
- **README 템플릿 개선**
  - 이 도구의 대상 스택(Maven + Thymeleaf)에 맞췄습니다. 원래는 Gradle과 `npm start` 기준이었습니다.
  - 이력서에 적은 구현 내용, 기술 스택, GitHub 주소, 기간, 역할, 성과를 자동으로 채웁니다.
  - "바로 실행하기", Spring 계층 폴더 구조, `application.yml` 예시, 트러블슈팅 섹션을 추가했습니다.
  - 편집기에 내용이 있으면 덮어쓰기 전에 확인합니다.
- **피드백 메시지 키보드 접근:** `Tab`으로 이동하고 `Enter`로 해당 칸으로 이동할 수 있습니다.

## 3. 이번에 반영하지 않은 개선 제안

규모가 크거나 동작 방식이 바뀌는 항목이라 따로 판단이 필요합니다.

1. **파일 분리:** 6,000줄 단일 파일이라 리뷰와 수정이 어렵습니다. `style.css`, `app.js`, 샘플 데이터(`samples.js`)로 나누는 것을 권장합니다. 다만 "파일 하나로 배포"가 장점이라면 빌드 단계에서 다시 합치는 방식이 좋습니다.
2. **인라인 `onclick` 제거와 CSP 적용:** 위자드와 샘플 패널은 아직 `onclick="Wizard.next()"` 형태입니다. 이벤트 위임으로 바꾸면 `Content-Security-Policy: script-src 'self'`를 적용해 XSS 방어를 한 단계 더 강화할 수 있습니다.
3. **API 키 보관 방식:** 지금은 localStorage에 평문으로 저장합니다. "이번 세션에만 기억"(sessionStorage) 옵션을 기본으로 두는 것을 고려해 볼 만합니다.
4. **`document.execCommand` 대체:** 붙여넣기와 복사에 쓰는 이 API는 폐기 예정입니다. 당장은 동작하지만 장기적으로 `Selection`/`Range` API로 바꿔야 합니다.
5. **점검 규칙 정밀화**
   - `containsMetric`는 숫자가 하나라도 있으면 "정량 성과"로 인정합니다. 예를 들어 "Spring Boot 3.x"도 통과합니다.
   - `hasPlaceholderText`는 `[`와 `]`가 둘 다 있으면 미작성으로 봅니다. 그래서 `arr[0]` 같은 코드 표기도 오탐합니다.
   - 둘 다 단위가 붙은 숫자나 대괄호 전체 패턴으로 좁히는 것이 좋습니다.
6. **자동 테스트:** 검증 엔진(`ValidationEngine`)과 마크다운 변환은 순수 함수에 가까워 단위 테스트를 붙이기 쉽습니다. 이번에 쓴 Playwright 시나리오를 저장소에 넣어 두는 것도 방법입니다.
7. **모바일 드래그:** 예시 패널 드래그가 마우스 이벤트만 처리합니다. Pointer Events로 바꾸면 터치에서도 동작합니다.
